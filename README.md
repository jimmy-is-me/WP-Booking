# WP Booking

由 WUMETAX 末特數位科技開發的繁體中文 WordPress 預約外掛，適用於工作室、顧問及其他一次接待一組客戶的服務。

## 安裝與設定

1. 在 GitHub 選擇 **Code → Download ZIP**，到 WordPress 後台的 **外掛 → 安裝外掛 → 上傳外掛** 上傳 ZIP 並啟用。
2. 在 **設定 → 一般** 設定網站時區。台灣網站可選 **台北**。
3. 前往 **預約管理 → 服務項目管理**，新增服務名稱、服務時間及選填的簡介與新台幣費用，並勾選「開放預約」。
4. 前往 **預約管理 → 排程與系統設定** 確認營業時間、休假日、預約開放天數和通知信箱。
5. 新增或編輯 WordPress 頁面，在 Gutenberg 的「短代碼」區塊加入 `[wp_booking]` 並發布。

系統需求為 WordPress 6.5 以上、64 位元 PHP 7.4 以上，以及支援 `GET_LOCK()` 的 MySQL 或 MariaDB。預約表單需要 JavaScript，且訪客須能存取此外掛的 WordPress REST API 路由。

## 升級

用 GitHub 的 **Code → Download ZIP** 下載新版後，先停用舊版，再上傳並啟用新版。WordPress 若出現「以上傳版本取代目前版本」的提示，可直接取代。若先前安裝的是指定提交的 ZIP，WordPress 可能因目錄名稱不同而列出兩個版本，請確認只啟用新版。既有服務、排程、預約和 `[wp_booking]` 都會沿用。

## 預約流程

- 訪客可透過服務卡片、月曆時段、聯絡資料和完成畫面四步完成預約。月曆會標示可預約、公休與額滿日期。
- 後台提供總覽儀表板、預約訂單列表、行事曆排程、服務項目管理及排程與系統設定。管理員可從後台替客戶新增預約，並在預約詳情記錄管理備註。
- 所有服務共用一份行事曆。同一時間可接受一筆預約。排程以 15 分鐘為刻度，服務長度可設為 15 至 480 分鐘。平日可設定多段營業時間。
- 「待確認」與「已確認」都會保留時段。管理員可在後台搜尋、篩選、確認或取消預約，服務時間結束後可將已確認的預約標為完成。取消會釋出時段。
- 新預約會寄信給客戶及指定的通知信箱。人工確認與取消會再通知客戶。寄信使用 WordPress 的 `wp_mail()`，請在正式開放前用實際收件信箱測試網站的寄信設定。
- 管理員可在訂單詳情直接改期。系統會確認新時段可用後一次更新，並保留原預約編號、服務長度、費用與變更紀錄。
- 客戶可用通知信中的專屬連結管理未開始的預約。取消與改期可分別開關，預設都在開始前 120 分鐘截止。改期後請用最新通知所附連結。
- 服務可設定前後緩衝、預約提前量與開放天數。特殊日期時段會取代每週設定，同日公休優先。服務或營業時間調整會保留既有預約。
- 待確認可設定逾時釋放，預設不限制。啟用後套用到新預約。已確認的服務結束後可標記未到場。
- 可為之後確認或改期的預約開啟開始前 24 小時或 2 小時提醒。通知排程與 WordPress 接受寄送或失敗結果可在訂單詳情查閱。

## 1.3.0 店家日常管理

- 「預約人員」角色可查看預約與行事曆、代客預約、確認、改期及填寫備註。服務及系統設定由網站管理員管理。
- 總覽提供今日行程、即將到期待確認、已過時待處理與寄送失敗入口，並依狀態列出本月服務金額。
- 在訂單詳情可重寄顧客的最新預約通知。設定頁可查閱排程上次完成與下次預定時間，並寄測試信至目前登入帳號的信箱。
- 顧客與店家可透過月曆查看可改期日期。服務可填寫出席地址或線上會議資訊，已確認的顧客可從通知連結開啟預約管理頁並下載 ICS 行事曆。

## 1.4.0 行事曆與介面

- 行事曆提供月曆及週排程，週排程會列出各日可營業的時段與有效預約。
- 網站管理員可一次停止開放最多 31 天、解除整天停約，或覆寫與清除指定日期的時段封鎖。既有預約保留。
- 訂單列表可加入服務篩選、用電話搜尋並切換排序。
- `[wp_booking_availability]` 只顯示服務與可預約時段。原有 `[wp_booking]` 仍用於接受預約。
- 外觀以黑白為主，西文字體使用 General Sans 與 Satoshi，中文字型使用本機可用字體。

## 資料與快取

- 預約資料儲存在 WordPress 資料庫的專用資料表。停用或重新啟用外掛會保留資料。
- 從 1.0.0 升級時會新增服務費用及管理備註欄位。服務費用以預約當時的設定為準。舊紀錄照原有資料顯示，金額會標示未設定。本月預估營收加總有記錄費用的未取消預約。
- 1.2.0 會在保留資料下新增通知紀錄與改期欄位。原有預約不會補排提醒或逾時。
- 提醒和逾時狀態更新由 WP-Cron 每五分鐘處理。低流量站可由主機固定呼叫 WordPress Cron。若使用全頁快取，請排除 `?wpb_manage=1` 的客戶管理頁。
- 可在 WordPress 的「工具」匯出或清除預約個資。清除會匿名化聯絡資料及備註，保留預約時段供排程使用。
- 前台會即時查詢服務與可用時段。若網站設有整站或 CDN 快取，請讓 `/wp-json/wp-booking/v1/` 下的 API 略過快取。使用普通永久連結時，對應的是 `rest_route=/wp-booking/v1/…`。
- 預約送出設有短期限流。反向代理環境應由主機正確還原可信任的訪客 IP，或由網站程式透過 `wpb_client_ip` 篩選器提供經驗證的來源 IP。

## WUMETAX 主機授權與更新

1. 在同一個 WordPress 站啟用 WU Toolbox Modular，並在工具箱完成既有的 WUMETAX 網站授權。
2. 安裝本專案 Release 的 `wp-booking.zip`。在「預約管理 → 授權與更新」可查看共用授權狀態。WP Booking 不另行發碼或呼叫授權伺服器。
3. 推送新版至 `main` 後，Actions 建立 Tag 與正式 GitHub Release。正式 Release 公開後，授權有效且允許更新的網站會在 WordPress 原生更新畫面看到新版。也可從 WP Booking 的授權頁立即檢查。
4. Toolbox 授權無效或外掛未啟用時，停止建立新預約，既有預約仍可管理。背景驗證與離線寬限沿用 Toolbox 判斷。

1.4.1 使用獨立授權流程，請以本版 ZIP 手動取代以遷移至共用授權。請勿在客戶站安裝舊版的獨立授權伺服器。GitHub 原始碼及客戶端 ZIP 為公開資源，授權站的客戶資料依照原先的 Toolbox 管理方式保留在中央站。
